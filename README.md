# CapitalPilot — کنترل سرمایه، تصمیم هوشمندانه

[English documentation](README.en.md) · [مستندات فارسی](README.md)

برنامهٔ وب فارسی و راست‌به‌چپ برای مدیریت سرمایه‌گذاری شخصی: داشبورد، چند سبد/استراتژی، دارایی‌ها و صندوق‌های کاملاً پویا، پلتفرم‌ها،
تراکنش‌ها، تقویم واریزی ماهانه، پیشنهاد خرید، مرکز ریسک، گزارش‌ها (Excel/CSV/PDF)، **موتور داده‌های بازار و صفحهٔ «منابع قیمت»**
و تنظیمات. نسخهٔ ۲ بدون بازنویسی ساخته شده و دادهٔ نسخهٔ ۱ با مهاجرت بدون‌اتلاف حفظ می‌شود.

> **این برنامه هیچ سفارش خرید یا فروشی ارسال نمی‌کند.** پیشنهادها فقط محاسبه‌اند؛ خرید را خودتان در پلتفرم انجام می‌دهید و سپس ثبت می‌کنید.
> این ابزار مشاورهٔ مالی نیست و هشدار افت سرمایه تضمینی برای جلوگیری از زیان بیشتر نیست.

## اجرای سریع

نیازمندی: Python 3.11 یا بالاتر (پیشنهادی ۳.۱۲+).

**Linux / Ubuntu / macOS**
```bash
./run.sh            # ساخت venv، نصب وابستگی‌ها و اجرا → http://127.0.0.1:8000
```

**Windows (PowerShell)**
```powershell
py -m venv .venv
.venv\Scripts\pip install -r requirements.txt
copy .env.example .env
.venv\Scripts\uvicorn app.main:app --port 8000
```

**Docker**
```bash
docker compose up -d --build     # دادهٔ برنامه در volume به نام capitalpilot-data (داخل کانتینر /data) ذخیره می‌شود؛ جزئیات: docs/DOCKER.md
```

مستندات Swagger: `http://127.0.0.1:8000/api/docs` — بررسی سلامت: `/api/health`

برای دسترسی از شبکه: `HOST=0.0.0.0 ./run.sh` (در این حالت حتماً `BASIC_AUTH_USER` و `BASIC_AUTH_PASSWORD` را در `.env` تنظیم کنید).

## استقرار Production روی سرور شخصی (نسخهٔ ۲٫۴٫۰)

بستهٔ `CapitalPilot-v2.4.0-production.zip` بدون `.env`، دیتابیس، کلید یا دادهٔ مالی ساخته می‌شود و پس از استخراج روی **Ubuntu 24.04 / Python 3.12 / systemd / Nginx / Let's Encrypt** اجرا می‌شود (SQLite پیش‌فرض).

```bash
sudo apt update && sudo apt install -y python3 python3-venv unzip curl nginx
sudo mkdir -p /opt && sudo unzip CapitalPilot-v2.4.0-production.zip -d /opt && sudo mv /opt/CapitalPilot-v2.4.0 /opt/capitalpilot
cd /opt/capitalpilot && sudo ./install.sh --domain capital.example.com --basic-auth admin --nginx
```

| فایل | کاربرد |
|---|---|
| `install.sh` | نصب: پیش‌نیازها، venv، وابستگی‌ها (با `requirements.lock`)، `.env` (فقط اگر نباشد)، مجوزها، migration، سرویس systemd، تایمر پشتیبان شبانه، بررسی سلامت. هرگز `.env`/دیتابیس موجود را بدون اجازه بازنویسی نمی‌کند |
| `update.sh` | به‌روزرسانی از ZIP جدید با پشتیبان دیتابیس/تنظیمات/کد، migration، بررسی سلامت و **بازگشت خودکار** در صورت خطا؛ `--rollback` برای بازگشت دستی |
| `backup.sh` / `restore.sh` | پشتیبان کامل قابل‌انتقال (اختیاری رمزنگاری‌شده) و بازیابی امن با نسخهٔ ایمنی |
| `python -m app.manage` | `version`، `check`، `migrate`، `backup`، `restore` |
| `deploy/` | قالب‌های systemd و Nginx |
| `VERSION`, `RELEASE_NOTES_fa.md` | نسخه و یادداشت‌های انتشار |

راهنماها: [نصب روی Ubuntu 24.04](docs/INSTALL-UBUNTU-24.04.md) · [Nginx و HTTPS](docs/NGINX-HTTPS.md) · [پشتیبان‌گیری و بازیابی](docs/BACKUP-RESTORE.md) · [اتصال منابع قیمت پس از استقرار](docs/PRICE-SOURCES.md) · [Docker](docs/DOCKER.md) · [امنیت](docs/SECURITY.md) · [مستندات API](docs/API.md)

مسیرهای پایدار پس از نصب: برنامه `/opt/capitalpilot`، تنظیمات `/opt/capitalpilot/.env` (مجوز 600)، دیتابیس `/var/lib/capitalpilot/capitalpilot.db`، پشتیبان‌ها `/var/lib/capitalpilot/backups` (مجوز 700، بیرون از مسیر وب)، لاگ `/var/log/capitalpilot`.

اعداد برنامه (هدف) **هرگز** به‌عنوان تراکنش واقعی ذخیره نمی‌شوند؛ هنگام اولین اجرا فقط دارایی‌ها، پلتفرم‌ها و تنظیمات ساخته می‌شود و
داشبورد تا ثبت اولین تراکنش واقعی پیام «هنوز تراکنشی ثبت نشده» نشان می‌دهد. برای ثبت واریزی ماه، از صفحهٔ «واریزی‌های ماهانه» استفاده کنید؛
مبلغ بین پلتفرم‌ها طبق ترکیب هدف تقسیم و تراکنش‌های واقعی ساخته می‌شود.

## قوانین محاسباتی

* همهٔ محاسبات مالی در بک‌اند و با `Decimal` انجام می‌شود (فرانت‌اند فقط نمایش می‌دهد).
* تعداد واحد و قیمت خرید جدا ذخیره می‌شوند؛ کارمزد در بهای تمام‌شدهٔ خرید لحاظ می‌شود.
* بهای تمام‌شده با روش **میانگین موزون**؛ سود فروش = (تعداد × قیمت − کارمزد) − (میانگین × تعداد).
* سود/زیان تحقق‌یافته و تحقق‌نیافته جدا هستند. واریز سود نیست و برداشت در بازدهی لحاظ می‌شود
  (ارزش فعلی + برداشت‌ها − واریزی‌ها = کل سود/زیان).
* بازدهی زمانی (TWR) و **XIRR**؛ در صورت کمبود داده (مثلاً کمتر از ۳۰ روز یا نبود قیمت معتبر) به‌جای عدد، دلیل نمایش داده می‌شود.
* قیمت «امروز» فقط وقتی معتبر است که تأییدشده، ثبت‌شده تا همان لحظه، هم‌واحد با دارایی و جدیدتر از حد مجاز (پیش‌فرض ۳ روز) باشد.
  قیمت کهنه هرگز به‌عنوان قیمت روز نشان داده نمی‌شود و ارزش‌گذاری را «ناقص» می‌کند.
* ویرایش یا حذف تراکنش، کل دفتر را دوباره بازپخش می‌کند؛ اگر نتیجه ناسازگار باشد (مثلاً فروش بیش از موجودی) رد می‌شود.
* افت سرمایه (Drawdown) از شاخص زمانی بازده تعدیل‌شده با جریان نقدی محاسبه می‌شود تا واریز جدید افت را پنهان نکند.
* پیشنهاد خرید: فقط خرید، تعداد صحیح واحد، با قیمت روز و کارمزد؛ بدون پیشنهاد فروش برای رسیدن به وزن هدف.

## مدیریت دارایی‌ها، پلتفرم‌ها و سبدها (نسخهٔ ۲)

هیچ دارایی، صندوق یا پلتفرمی در کد ثابت نیست؛ همه از رابط کاربری اضافه، ویرایش و بایگانی می‌شوند.

* **دارایی‌ها و صندوق‌ها** یک ساختار مشترک دارند: نام فارسی/انگلیسی، نماد، نوع، بازار، پلتفرم، واحد سنجش، واحد پول، اعشار مجاز،
  حداقل مقدار خرید، وزن هدف، قیمت اولیهٔ خرید (اختیاری و فقط اطلاعاتی)، توضیحات، فعال/غیرفعال، منابع قیمت و شناسه در هر منبع
  (مثلاً insCode در TSETMC). هر نوع می‌تواند فیلدهای اختصاصی داشته باشد (مثلاً «نوع صندوق»، «عیار»).
* **انواع دارایی پویا:** صندوق، سهام، رمزارز، طلا، نقره، مس، ارز، درآمد ثابت، کالا، شاخص، سایر و هر نوع جدیدی که خودتان تعریف کنید
  (با رنگ و فیلدهای دلخواه) از «دارایی‌ها ← مدیریت انواع دارایی».
* **پلتفرم‌ها** بخش مستقل‌اند (مفید، بیت‌پین، بورس، بورس کالا، کارگزاری دیگر، بازار خارجی، شخصی، سایر + هر چه اضافه کنید).
  هر دارایی به یک پلتفرم وصل است؛ یک ابزار روی چند پلتفرم، به‌صورت دو دارایی با موجودی و شناسهٔ مستقل ثبت می‌شود.
* **سبدها/استراتژی‌ها:** هر سبد سرمایه، واریزی ماهانه، افق، سقف افت، تاریخ شروع، دارایی‌های عضو و وزن هدف خودش را دارد
  (حالت درصدی با مجموع دقیقاً ۱۰۰٪ یا مبلغ ثابت). تراکنش‌ها، برنامهٔ واریزی، ارزش‌گذاری و ریسک برای هر سبد جدا محاسبه می‌شود.
  سبد فعال را از کنار عنوان بالای صفحه عوض می‌کنید. حذف دارایی از یک سبد هرگز تراکنش‌هایش را پاک نمی‌کند.

### حذف امن (Soft delete)

| وضعیت | کار مجاز |
|---|---|
| دارایی/پلتفرم/سبد بدون تراکنش و وابستگی | حذف کامل (با تأیید) |
| دارای تراکنش | فقط **بایگانی**؛ سابقه، سود/زیان گذشته و گزارش‌ها حفظ می‌شود؛ در پیشنهاد خرید و ثبت خرید جدید ظاهر نمی‌شود؛ قابل بازیابی |
| دارای وابستگی ولی بدون تراکنش (قیمت، منبع، عضویت سبد) | حذف دائمی فقط پس از بررسی وابستگی‌ها و تأیید چندمرحله‌ای: درخواست ← تایپ عبارت «حذف دائمی» ← اجرا (توکن ۵ دقیقه‌ای، پشتیبان خودکار قبل از حذف) |

دارایی یا پلتفرمی که تراکنش دارد هیچ‌گاه حذف دائمی نمی‌شود.

## موتور داده‌های بازار و منابع قیمت

بسته‌ای مستقل در `app/services/marketdata/` با قرارداد یکسان برای همهٔ ارائه‌دهنده‌ها: قیمت جاری، اطلاعات نماد، تاریخچه،
بررسی سلامت، گزارش خطا، زمان آخرین دریافت و واحد قیمت.

| ارائه‌دهنده | توضیح | وضعیت راستی‌آزمایی |
|---|---|---|
| `TSETMCProvider` | آخرین معامله، قیمت پایانی، NAV (فقط وقتی معتبر باشد)، تاریخچه، زمان به‌روزرسانی، جستجو و انتخاب نماد؛ ریال به تومان تبدیل می‌شود | نشانی‌ها از کلاینت متن‌باز `pytse-client` ‏(0.19.1) |
| `BitpinProvider` | فهرست بازارها، قیمت لحظه‌ای و آخرین معامله، تغییر ۲۴ساعته، تاریخچه (TradingView bars) از API عمومی؛ فقط بازار تکی مثل `BTC_IRT`. **سبدهای آمادهٔ سرمایه‌گذاری تیکر نیستند** و رد می‌شوند (برای آن‌ها قیمت دستی یا منبع اختصاصی) | نشانی‌ها از پروژه‌های متن‌باز بیت‌پین؛ مستندات رسمی از سندباکس در دسترس نبود |
| `StreamDataProvider` | سهام/شاخص خارجی؛ آدرس و کلید از ENV یا پنل؛ قیمت و ارز ثبت می‌شود و تبدیل به تومان جدا با نرخ ارز ثبت‌شده انجام می‌شود | **بدون آدرس پیش‌فرض**؛ مستند عمومی راستی‌آزمایی نشد → آداپتور JSON قابل‌پیکربندی |
| `ServixProvider` | اختیاری (طلا، ارز و …) | همانند بالا |
| `CustomAPIProvider` | هر API با پاسخ JSON: آدرس، احراز هویت (None/Bearer/هدر/کوئری)، پارامترها، مسیر JSONPath یا نگاشت فیلد قیمت/زمان/واحد، ضریب | کاملاً کاربرمحور |
| `ManualPriceProvider` | ثبت دستی؛ همیشه به‌عنوان آخرین گزینه | — |

> **صادقانه:** محیط ساخت به سرویس‌های ایرانی دسترسی نداشت، پس اتصال زنده به TSETMC/بیت‌پین آزموده نشده است. آزمون‌های خودکار با `httpx.MockTransport`
> و نمونهٔ پاسخ‌های مستندشده انجام شده‌اند. پس از اجرا روی شبکهٔ خودتان از «منابع قیمت ← تست اتصال» استفاده کنید؛ هر ناهمخوانی در نشانی را
> می‌توانید با `TSETMC_BASE_URL` / `BITPIN_BASE_URL` یا در پنل اصلاح کنید. نرخ تبدیل ارز به تومان خودکار دریافت نمی‌شود و از جدول نرخ دستی می‌آید.

### صفحهٔ «منابع قیمت»
افزودن/ویرایش/غیرفعال/بایگانی منبع، آدرس، نوع احراز هویت، کلید API (فقط‌نوشتنی؛ **هرگز به مرورگر برنمی‌گردد**، با Fernet رمزنگاری می‌شود و در پشتیبان نیست)،
پارامترهای درخواست، مسیر JSON قیمت، واحد پول ورودی، بازهٔ به‌روزرسانی، تقویم بازار، سقف نرخ درخواست، تلاش مجدد، تست اتصال،
نتیجه و خطای آخرین درخواست، لاگ‌ها و تنظیمات زمان‌بند.

### اولویت منبع هر دارایی و قواعد اعتبار قیمت
* برای هر دارایی ترتیب منابع (اصلی ← جایگزین ← دستی) تعریف می‌شود. خطای منبع اصلی لاگ می‌شود و منبع بعدی امتحان می‌شود.
* اگر همه شکست بخورند، «در دسترس نیست یا کهنه» نشان داده می‌شود؛ **هیچ قیمت قدیمی‌ای به‌عنوان قیمت زنده نمایش داده نمی‌شود.**
* قیمت نامعتبر (صفر/منفی، ناهمخوانی واحد، آینده، کهنه) با دلیل در جدول ثبت می‌شود اما در ارزش‌گذاری و نمودار نمی‌آید و جایگزین قیمت معتبر نمی‌شود.
* قیمت تکراری (همان دارایی/منبع/زمان منبع/نوع) دوباره ذخیره نمی‌شود. قیمت خودکار فقط وقتی «تأییدشده» است که منبع «تأیید خودکار» داشته باشد؛ وگرنه تا تأیید دستی در ارزش‌گذاری نیست.
* هر رکورد قیمت: دارایی، منبع، قیمت، واحد، زمان دریافت، زمان منبع، اعتبار، تأیید و توضیح. صفحهٔ دارایی نمودار تاریخچه و مقایسهٔ منابع را نشان می‌دهد.

### زمان‌بند مستقل
بازهٔ پیش‌فرض و بازهٔ هر منبع/دارایی، فقط در ساعات بازار (بورس تهران: شنبه تا چهارشنبه ۰۸:۴۵–۱۲:۴۵ به وقت تهران؛ رمزارز ۲۴ساعته)،
کش ۱۵ ثانیه‌ای و حذف درخواست تکراری هم‌زمان، سقف نرخ درخواست، تلاش مجدد با backoff نمایی، لاگ و ثبت آخرین دریافت موفق.
با `SCHEDULER_ENABLED=false` کلاً خاموش می‌شود. تعطیلات رسمی شناسایی نمی‌شود (تقویم بازار فقط روزهای هفته و ساعت است).

### قیمت دستی و نرخ ارز
ورود دستی قیمت (با تاریخ/ساعت و تأیید) همیشه کار می‌کند؛ نرخ ارز جداگانه ثبت می‌شود.

## مرکز هوشمندی قیمت‌ها و کنترل کیفیت (نسخهٔ ۲٫۱)

صفحهٔ **«مرکز هوشمندی قیمت‌ها»** (`#/intelligence`) فقط می‌خواند، تحلیل می‌کند و پیشنهاد می‌دهد؛ **هیچ سفارش خرید یا فروشی ثبت نمی‌شود** و هر تصمیم مالی با تأیید دستی شماست.
همهٔ اعداد از قیمت‌ها و لاگ واقعی درخواست‌ها محاسبه می‌شود؛ هیچ داده نمایشی یا آزمایشی به‌عنوان قیمت واقعی نشان داده نمی‌شود.

* **نمای کلی منابع:** تعداد منابع فعال/غیرفعال/دارای خطا، آخرین دریافت موفق، زمان پاسخ، درصد موفقیت و تعداد خطا برای هر منبع.
* **پایش دارایی‌ها:** قیمت و واحد، منبع و منشأ (دستی/آنلاین)، زمان و سن قیمت، تأخیر داده، وضعیت (معتبر، قدیمی، نامعتبر، دستی، ناموجود، اختلاف منابع)، اختلاف قیمت بین منابع،
  زنجیرهٔ منابع (اصلی ← جایگزین)، تشخیص قطع منبع اصلی، «آخرین قیمت موفق» جدا از «آخرین تلاش دریافت»، و ردپای تبدیل (مقدار خام، واحد، ریال↔تومان، نرخ ارز).
  از همین‌جا اولویت منابع هر دارایی تغییر می‌کند و «مقایسه» قیمت را از همهٔ منابع می‌گیرد (برای دیدن اختلاف).
* **هشدارهای هوشمند** (در هر درخواست از وضعیت جاری محاسبه می‌شوند): قیمت قدیمی، اختلاف غیرعادی منابع، تغییر شدید، قطع منبع، واحد پول اشتباه، قیمت صفر/منفی/نامعتبر، عدم تطابق زمان داده با زمان دریافت.
* **گزارش عملکرد و تاریخچه:** نمودار نرخ موفقیت، زمان پاسخ، درخواست و خطای روزانهٔ هر منبع و جدول لاگ با فیلتر تاریخ (شمسی)، منبع، دارایی و نتیجه.

### لایهٔ کنترل کیفیت قیمت (`app/services/marketdata/quality.py`)
* قیمت آنلاین هیچ‌گاه بدون منبع و زمان دریافت ذخیره نمی‌شود؛ اگر منبع زمان قیمت را اعلام نکند برچسب `no_source_time` می‌خورد و زمان دریافت ثبت می‌شود.
* قیمت صفر/منفی، زمان آینده و قیمت کهنه ثبت می‌شود اما نامعتبر است، در ارزش‌گذاری نمی‌آید و **قابل تأیید نیست** (تأیید قیمت نامعتبر → خطای ۴۲۲).
* تبدیل ریال/تومان/ارز شفاف است: مقدار خام، واحد خام و توضیح تبدیل روی هر رکورد می‌ماند؛ تبدیل ارز خارجی خودکار و خاموش انجام نمی‌شود (نیاز به نرخ ارز ثبت‌شده).
* **اختلاف غیرعادی منابع** (پیش‌فرض بیش از ۱۰٪ بین قیمت‌های تازهٔ دو منبع): سیستم یکی را خودسرانه انتخاب نمی‌کند؛ دارایی در وضعیت «اختلاف منابع» می‌ماند و در ارزش‌گذاری نمی‌آید تا شما قیمت دستی تازه ثبت کنید یا یکی از قیمت‌ها را صریحاً تأیید کنید.
* هر قیمت دارای `origin` (`manual` / `online`) است؛ حذف یا تغییر منبع قیمت، منشأ و تاریخچهٔ قیمت‌های ثبت‌شده و تراکنش‌ها را تغییر نمی‌دهد.
* آستانه‌ها با `QUALITY_*` در `.env` قابل تنظیم است (`.env.example`).
* جایگزین فقط وقتی استفاده می‌شود که دادهٔ آن معتبر باشد، و مسیر کامل دریافت (`via`) روی رکورد ذخیره می‌شود.

API فقط‌خواندنی: `GET /api/market-data/intelligence/{overview,assets,alerts,performance,logs}`. گزینهٔ `POST /api/assets/{id}/refresh-price?all_sources=true` همهٔ منابع را برای مقایسه می‌خواند.

## بازار جامع ایران — Iran Market Data (نسخهٔ ۲٫۳)

یک منبع **مکمل و انتخابی** برای قیمت هزاران نماد (ارز، طلا، سکه، رمزارز، کالا، انرژی، فلزات گرانبها، شاخص‌ها) از فایل عمومی و بدون کلید
[`latest-toman.json`](https://raw.githubusercontent.com/iran-market/iran-market.github.io/main/data/latest-toman.json)
(پروژهٔ [iran-market/iran-market.github.io](https://github.com/iran-market/iran-market.github.io)؛ دادهٔ هر نماد متعلق به منبع اصلی‌اش، مثل tgju، است و فقط اطلاع‌رسانی است).
جایگزین اجباری TSETMC یا بیت‌پین نیست و **به‌طور پیش‌فرض غیرفعال** است (فعال‌سازی: «منابع قیمت» یا دکمهٔ «فعال‌سازی منبع» در صفحهٔ «بازار جامع ایران»).

**معماری:** فقط Backend فایل را دریافت می‌کند (یک درخواست برای همهٔ نمادها؛ `If-None-Match`/ETag، هش sha256 برای تشخیص فایل تکراری، retry با backoff، حداقل فاصلهٔ ۱۰ ثانیه بین دو درخواست، سقف حجم، بدون redirect)،
ساختار تو‌در‌توی واقعی (`data.categories.<دسته>[رکورد]` و `meta`) را می‌خواند و هر نماد را در جدول `market_symbols` نگه می‌دارد. جست‌وجو، فیلتر، مرتب‌سازی و صفحه‌بندی روی دیتابیس انجام می‌شود؛
هیچ درخواست کاربری باعث دانلود نمی‌شود. زمان‌بند مستقل هر ۳۰ دقیقه (قابل تنظیم در منبع) فایل را می‌گیرد و پس از دریافت تازه، فقط دارایی‌های متصل را دوباره قیمت‌گذاری می‌کند. پاسخ خام فشرده برای عیب‌یابی (۵ دریافت آخر؛ `IRANMARKET_RAW_KEEP`) و تاریخچهٔ دریافت‌ها در `market_snapshots` ذخیره می‌شود.
اگر API قطع شود آخرین داده نگه داشته می‌شود ولی پس از `max(۹۰ دقیقه، ۳×بازه)` (یا `IRANMARKET_STALE_AFTER_MINUTES`) همهٔ قیمت‌ها «قدیمی» می‌شوند و در ارزش‌گذاری نمی‌آیند.

**آدرس و آینه:** پیش‌فرض آدرس raw گیت‌هاب است. در شبکه‌هایی که آن میزبان بسته است می‌توانید در «ویرایش منبع ← آدرس API» (یا `IRANMARKET_URL`) آینهٔ jsDelivr
`https://cdn.jsdelivr.net/gh/iran-market/iran-market.github.io@main/data/latest-toman.json` را بدهید. توجه: طبق مستندات منبع، jsDelivr ممکن است تا ~۱۲ ساعت کش داشته باشد و در آن صورت داده‌ها به‌درستی «قدیمی» علامت می‌خورند.
تاریخچهٔ نمودار از مسیر مستند همان پروژه (`history/index.json` و `history/{SYMBOL}.json`، در همان پوشه) خوانده و فقط نمایش داده می‌شود؛ در جدول قیمت‌ها ذخیره نمی‌شود.

**وضعیت مستقل هر نماد** (موفقیت دریافت فایل، همهٔ قیمت‌ها را معتبر نمی‌کند):
`معتبر` / `معتبر با هشدار کیفیت` (spike، ohlc_inconsistent از منبع) / `قدیمی` (`stale=true`، قیمت قدیمی‌تر از `max_price_age_days`، نبودن در آخرین فایل یا قدیمی بودن کل داده) / `نامعتبر` (قیمت ≤ ۰ یا غیرعددی، زمان نامعتبر یا آینده، نبودن ارز) / `بدون قیمت` (`null`؛ هرگز صفر فرض نمی‌شود).
فقط وضعیت معتبر وارد ارزش‌گذاری می‌شود. `timestamp` (زمان قیمت)، `checked_at` (زمان بررسی منبع)، `generated_at` (زمان تولید فایل) و زمان دریافت CapitalPilot جدا ذخیره می‌شوند؛ `source` اصلی هر نماد (در `prices.upstream_source`) نگه‌داری می‌شود.

**ارز و واحد:** قیمت‌ها با ارز و واحد خودِ فایل ذخیره می‌شوند (تومانی‌ها هرگز ×۱۰ یا ÷۱۰ نمی‌شوند؛ جهانی‌ها مثلاً USD). تبدیل ضمنی وجود ندارد: دارایی با واحد پول متفاوت فقط با نرخ ارز ثبت‌شده و معتبر ارزش‌گذاری می‌شود (موتور کیفیت v2.1).
نمادهایی که قیمتشان برای اندازهٔ واحد ≠ ۱ است (مثل `JPY_IRR_FREE` برای ۱۰۰ ین) یا ارز نامشخص دارند قابل اتصال نیستند؛ برای نمادهای دارای واحد (گرم، عدد سکه، اونس، بشکه، مثقال) کاربر هنگام اتصال صراحتاً «قیمت هر ... است» را تأیید می‌کند.

**اتصال نماد به دارایی (مهم‌ترین بخش):** در فرم دارایی (و «اولویت منابع» مرکز هوشمندی) منبع «Iran Market Data» را اضافه و نماد را از پنجرهٔ جست‌وجو انتخاب می‌کنید؛ قیمت، ارز، واحد، وضعیت و زمان را می‌بینید و باید صراحتاً تأیید کنید.
تطبیق خودکار نام وجود ندارد (پیشنهادها فقط راهنما هستند و `auto_link=false`)، به هر دارایی فقط یک نماد وصل می‌شود، نمادها هرگز خودکار به دارایی تبدیل نمی‌شوند و قطع/تغییر اتصال به قیمت‌ها و تراکنش‌های ثبت‌شده دست نمی‌زند.
اگر پس از تأیید، ارز/واحد/اندازهٔ واحد نماد در فایل عوض شود، دریافت قیمت آن دارایی با خطای `link_changed` متوقف می‌شود تا دوباره تأیید کنید.
اولویت منابع هر دارایی آزاد است (مثلاً TSETMC ← Iran Market ← دستی)؛ اولین منبع معتبر برنده است و در صورت خطا یا قدیمی/نامعتبر بودن، منبع بعدی امتحان می‌شود. اختلاف غیرعادی منابع طبق موتور کیفیت ۲٫۱ «اختلاف منابع» است و قیمتی انتخاب نمی‌شود.

**صفحهٔ «بازار جامع ایران»** (`#/iran-market`): شاخص‌ها (تعداد نماد، معتبر، قدیمی، بدون قیمت، تعداد دسته، زمان تولید فایل، وضعیت اتصال)، چیپ دسته‌ها (استخراج‌شده از خود فایل)،
جست‌وجوی فارسی/انگلیسی/نماد، فیلتر بازار/ارز/وضعیت/متصل، مرتب‌سازی عددی روی قیمت و درصد تغییر، صفحه‌بندی؛ جزئیات هر نماد (`#/iran-market/s/SYMBOL`: قیمت، تغییر، منبع، زمان‌ها، هشدارهای کیفیت، نمودار تاریخچه، دارایی‌های متصل) و تب «دریافت‌ها و سلامت» (آخرین موفقیت، زمان تولید فایل، زمان پاسخ، خطاها، تاریخچهٔ دریافت‌ها و دانلود پاسخ خام).
در «منابع قیمت» کارت منبع: فعال/غیرفعال، تست اتصال، دریافت دستی، بازه، آخرین موفقیت، تعداد نماد، خطاها، زمان پاسخ، زمان تولید فایل و تعداد قدیمی‌ها را نشان می‌دهد.

**API** (`/api/iran-market`): `overview`، `symbols` (q، category، market، currency، status، linked، sort، order، page)، `symbols/{symbol}`، `symbols/{symbol}/history`، `symbols/{symbol}/stored-prices`، `POST refresh` (۴۰۹ `provider_disabled` وقتی منبع غیرفعال است)، `snapshots`، `snapshots/{id}/raw`، `suggest`، `POST|DELETE link`.
متغیرهای محیطی: `IRANMARKET_URL`، `IRANMARKET_MAX_BYTES`، `IRANMARKET_RAW_KEEP`، `IRANMARKET_STALE_AFTER_MINUTES`، `IRANMARKET_HISTORY_TTL_MINUTES` (نمونه در `.env.example`).

## جست‌وجوی سراسری بازار (نسخهٔ ۲٫۴)

**کجا:** کادر «جست‌وجوی سراسری بازار…» همیشه در نوار بالای دسکتاپ هست؛ در موبایل (زیر ۷۲۰px) به آیکن ذره‌بین هدر تبدیل می‌شود و پنل تمام‌صفحه باز می‌کند.
میانبرها: **Ctrl+K** (در مک **⌘K**) باز/بسته می‌کند، **Esc** می‌بندد، فوکوس مستقیم روی کادر ورودی می‌رود؛ ↑ ↓ حرکت، Enter انتخاب، Tab درون پنل می‌ماند.
نتایج بدون بارگذاری مجدد صفحه می‌آیند.

**چه چیزی جست‌وجو می‌شود** (فقط دادهٔ واقعی دیتابیس؛ هیچ فهرست ساختگی‌ای وجود ندارد): همهٔ نمادهای «بازار جامع ایران» (`market_symbols`: ارز، طلا و سکه، صندوق‌های طلا، رمزارز، کالا و انرژی، شاخص‌ها، …)،
دارایی‌های خودتان، پلتفرم‌ها و بازارهای تعریف‌شده. تطبیق روی نام فارسی، نام انگلیسی، نماد معاملاتی، کد دارایی، نام دسته و نام بازار انجام می‌شود.
اگر هنوز دادهٔ بازار دریافت نشده باشد، نوار هشدار می‌گوید و فقط دارایی‌ها/پلتفرم‌ها/بازارهای ثبت‌شده پیدا می‌شوند.

**هوشمندی جست‌وجو** (`app/services/search.py`): یکسان‌سازی «ی/ي»، «ک/ك»، همزه/تنوین/کشیده، اعداد فارسی/عربی/انگلیسی، فاصلهٔ اضافه و نیم‌فاصله؛
ورودی ناقص نماد (`GOLD_18`)؛ مترادف‌ها («دلار»، «طلا»، «بیت‌کوین»، …)؛ تطبیق تقریبی برای غلط املایی (مثل «بیتکون»، «دلر») که فقط وقتی تطبیق دقیقی نباشد وارد می‌شود و برچسب «تطبیق تقریبی» می‌گیرد.
ترتیب نتایج بر اساس کیفیت تطبیق: نماد دقیق ← کد دقیق ← نام دقیق ← شروع/کلمهٔ نام ← شامل‌بودن در نام ← نام انگلیسی ← مترادف ← دسته/بازار ← تقریبی.

**ردیف نتیجه:** نام فارسی، نام انگلیسی، نماد، دسته، بازار، آخرین قیمت، واحد پول، درصد تغییر، منبع قیمت، زمان/سن قیمت و وضعیت (معتبر / قدیمی / نامعتبر / ناموجود).
نتایج در گروه‌های دسته‌بندی‌شده (۵ مورد برتر هر گروه + «مشاهدهٔ همهٔ N نتیجه») و با فیلترهای سریع نمایش داده می‌شوند: همه، دارایی‌های من، ارز، طلا و سکه، صندوق‌ها، بورس، رمزارز، کالا و انرژی، سایر. فیلتر یک دسته ۳۰تا۳۰تا صفحه‌بندی می‌شود («نمایش بیشتر»).

**قیمت قدیمی و نامعتبر:** قیمت قدیمی با هشدار «قیمت قدیمی؛ زنده نیست» و کمرنگ نشان داده می‌شود و هرگز با برچسب «معتبر» نمی‌آید؛ قیمت نامعتبر یا ناموجود اصلاً عدد نشان نمی‌دهد (`—`) و در ارزش‌گذاری به کار نمی‌رود.

**عملکرد و آفلاین:** مرورگر فقط به API همین برنامه وصل می‌شود و `GET /api/search` هرگز به شبکه/منبع بیرونی نمی‌رود؛ خواندن از دیتابیس/آخرین دادهٔ ذخیره‌شده است، پس بدون اینترنت هم کار می‌کند (نوار هشدار «اینترنت قطع است / داده‌ها قدیمی‌اند»).
تأخیر ۲۵۰ms (Debounce) و نادیده‌گرفتن پاسخ‌های کهنه. فقط «نمودار/تاریخچه» با کلیک روی همان زبانه، فایل تاریخچهٔ منبع را از طریق Backend می‌خواند (با کش) و در صورت قطع بودن، به قیمت‌های ذخیره‌شده برمی‌گردد.
جست‌وجوهای اخیر (حداکثر ۸ مورد) و پیشنهادهای محبوب (از دادهٔ واقعی؛ نمادهای متصل به دارایی‌های شما اول) نمایش داده می‌شوند؛ اخیرها فقط در `localStorage` همین مرورگر (`cp.gs.recent`) می‌مانند و دکمهٔ «پاک‌کردن تاریخچه» دارند.

**اقدام روی هر نتیجه** (پنل جزئیات با زبانه‌های خلاصه، نمودار قیمت، تاریخچهٔ قیمت و منبع قیمت): جزئیات کامل، اتصال به دارایی موجود (اول سبد، بعد دارایی)، ساخت دارایی جدید از نماد، افزودن به سبد.
همهٔ این‌ها فقط با تأیید صریح (چک‌باکس + دکمهٔ تأیید؛ در API `confirm: true`) انجام می‌شوند. اگر نماد قبلاً به دارایی‌ای وصل باشد، نام آن دارایی نشان داده می‌شود و اتصال/ساخت تکراری هم در رابط و هم در سرور (۴۰۹) رد می‌شود.
**ساخت دارایی هیچ تراکنش خرید، موجودی یا سفارشی ایجاد نمی‌کند** (وزن هدف ۰، منبع قیمت تأییدشده)، و جست‌وجو خودش چیزی در دیتابیس نمی‌نویسد.

**API** (`/api/search`): `GET ""` (`q`، `group`، `page`، `page_size`، `per_group`)، `GET /suggestions`، `POST /link`، `POST /create-asset`، `POST /add-to-portfolio` (هر سه `confirm: true` می‌خواهند و در غیر این صورت ۴۲۲ `not_confirmed`).

**محدودیت‌ها (صادقانه):** جست‌وجوی آنلاین TSETMC و بیت‌پین در این نسخه نیست (فقط نمادهایی که قبلاً در `market_symbols` ذخیره شده‌اند و دارایی‌های شما)؛ فایل Iran Market از محیط توسعه قابل دریافت نبود،
بنابراین دریافت زندهٔ واقعی تأیید نشد و آزمون‌ها با نسخهٔ واقعی ذخیره‌شدهٔ فایل (۱۰۴۲ نماد) اجرا می‌شوند. هیچ دادهٔ دمو یا ساختگی به دیتابیس اضافه نمی‌شود.

## مهاجرت پایگاه‌داده

هنگام اجرا، `app/migrations` نسخهٔ طرح‌واره را بررسی می‌کند. روی دیتابیس نسخهٔ ۱: ابتدا پشتیبان کامل فایل در `data/backups`، سپس مهاجرت در تراکنش
(`m001` پایه، `m002` مدیریت پویا، `m003` کیفیت قیمت: ستون‌های `origin`، قیمت خام، برچسب‌های کیفیت و …، `m004` Iran Market Data: ستون‌های `upstream_source/upstream_checked_at/snapshot_id` در قیمت‌ها، `link_meta` در منابع دارایی، جدول‌های `market_snapshots` و `market_symbols` و منبع غیرفعال). همهٔ تراکنش‌ها، قیمت‌ها و تنظیمات حفظ می‌شود، یک «سبد اصلی» از تنظیمات قبلی ساخته می‌شود و تراکنش‌ها به آن وصل می‌شوند.
آزمون `tests/test_migration.py` همین مسیر را روی یک دامپ واقعی نسخهٔ ۱ اجرا و عددبه‌عدد (ارزش، سود/زیان، XIRR) مقایسه می‌کند.

Swagger/OpenAPI تعاملی در `/api/docs` (و `/api/openapi.json`). گروه‌های اصلی:

| مسیر | کاربرد |
|---|---|
| `/api/assets` | فهرست (جستجو، فیلتر نوع/پلتفرم/وضعیت، مرتب‌سازی، صفحه‌بندی)، ساخت، ویرایش، `archive`، `restore`، `dependencies`، `price-sources`، `refresh-price`، `purge/request` و `purge/confirm` |
| `/api/asset-types` | انواع دارایی پویا |
| `/api/platforms` | CRUD، `archive`، `restore` |
| `/api/portfolios` | CRUD، `targets`، `assets`، `archive`، `restore`، `make-default` |
| `/api/market-data` | `kinds`، `status`، `providers` (CRUD، `enable`، `test`، `search`، `history`، `logs`)، `refresh`، `history`، `history/import`، `scheduler` |
| `/api/iran-market` | بازار جامع ایران: نمادها، دسته‌ها، دریافت دستی، تاریخچه، اتصال تأییدشدهٔ نماد به دارایی |
| `/api/search` | جست‌وجوی سراسری بازار (نتایج گروه‌بندی‌شده، پیشنهادها) و اقدام‌های تأییدشده: اتصال، ساخت دارایی، افزودن به سبد |
| `/api/prices`, `/api/fx` | ثبت و تأیید قیمت، نرخ ارز |
| `/api/transactions`, `/api/contributions`, `/api/rebalance`, `/api/risk`, `/api/reports`, `/api/dashboard`, `/api/portfolio` | مانند نسخهٔ ۱؛ همه پارامتر `portfolio_id` را می‌پذیرند |
| `/api/backup`, `/api/data` | پشتیبان، بازیابی، پاک‌سازی دومرحله‌ای |

## گزارش‌ها

روزانه، ماهانه، فصلی، سالانه، کل دوره، سود و زیان هر دارایی، واریزی‌ها، برداشت‌ها، عملکرد پلتفرم‌ها، مقایسه با ترکیب هدف و ریسک.
خروجی Excel حاوی عدد واقعی (نه متن) با قالب هزارگان، CSV (UTF-8 با BOM) و PDF فارسی است.

## پشتیبان‌گیری و پاک‌سازی

* «تنظیمات ← دریافت پشتیبان JSON» و بازیابی از فایل (با تأیید و اعتبارسنجی کامل پیش از دست‌زدن به پایگاه‌داده).
* پشتیبان فایل دیتابیس روی سرور در `data/backups`.
* پاک‌سازی داده در چند مرحله: تأیید، تایپ عبارت امنیتی و اجرای نهایی؛ پیش از آن پشتیبان خودکار گرفته می‌شود.

## PostgreSQL

`pip install "psycopg[binary]"` و در `.env`: `DATABASE_URL=postgresql+psycopg://user:pass@localhost:5432/capitalpilot`.
مدل‌ها با SQLAlchemy 2 نوشته شده و ستون‌های پولی در SQLite به‌صورت متن (برای حفظ دقت Decimal) و در PostgreSQL به‌صورت `NUMERIC(38,12)` ذخیره می‌شوند.

```bash
python -m pytest -q                      # همهٔ آزمون‌های Python (+ پوشش رابط کاربری در صورت وجود Node و Chrome)
```

* **Python:** محاسبات مالی، API، مدیریت پویا، موتور داده بازار، مهاجرت از دامپ واقعی نسخهٔ ۱ (شامل پُرشدن `origin`)، لایهٔ کنترل کیفیت (اعتبار قیمت، اختلاف منابع، fallback، هشدارها، آمار منابع و لاگ‌ها، آخرین قیمت موفق در برابر آخرین تلاش) و اینکه حذف/تغییر منابع، تراکنش‌ها و قیمت‌های ثبت‌شده را دست‌نخورده می‌گذارد.
* **Iran Market Data** (`tests/test_iranmarket.py`، ۳۲ آزمون): با نسخهٔ واقعی ذخیره‌شدهٔ فایل (`tests/fixtures/iranmarket_latest_toman_20261104.json.gz`، ۱۰۴۲ نماد و ۹ دسته) و MockTransport (بدون شبکه): دریافت و پردازش، همهٔ دسته‌ها، استخراج و حفظ فیلدها، تشخیص stale، زمان نامعتبر/آینده، قیمت صفر/منفی/null، ارز و واحد، تطابق SQL و Python در وضعیت‌ها، اتصال با تأیید، انسداد ارز/واحد ناسازگار، ارزش‌گذاری، اولویت و fallback، اختلاف غیرعادی، قطع API، جلوگیری از داده تکراری و دانلود شرطی، جست‌وجو/فیلتر/مرتب‌سازی/صفحه‌بندی، زمان‌بند، تاریخچه، پشتیبان و مهاجرت. زمان‌های فایل واقعی برای پایداری آزمون به «اکنون» منتقل می‌شود.
* **جست‌وجوی سراسری** (`tests/test_search.py`، ۳۵ آزمون): نام فارسی/انگلیسی، نماد، اعداد فارسی و انگلیسی، ی/ک، گروه‌بندی و صفحه‌بندی، رتبه‌بندی، مترادف و غلط املایی، فقط دادهٔ واقعی، قیمت قدیمی/نامعتبر هرگز زنده نیست، آفلاین (بدون هیچ درخواست شبکه)، اتصال/ساخت/افزودن با تأیید، جلوگیری از اتصال تکراری، نبودن تراکنش و موجودی، فقط‌خواندنی بودن جست‌وجو و سرعت.
* **رابط کاربری** (`tests/frontend`، با `tests/test_frontend.py` اجرا می‌شود و بدون Node یا مرورگر skip می‌شود):
  `cd tests/frontend && npm install` سپس `pytest tests/test_frontend.py`. یک سرور و دیتابیس موقت جدا بالا می‌آید (به داده‌های شما دست نمی‌زند).
  آزمون واحد `node:test` برای قالب‌بندی و تبدیل ورودی؛ آزمون Puppeteer برای: جست‌وجوی سراسری (۷ آزمون: دسکتاپ، میانبرها، موبایل ۳۹۰، قیمت قدیمی، اتصال، ساخت دارایی، آفلاین/Debounce)، همهٔ مسیرها در دسکتاپ (بدون خطای کنسول و بدون رقم لاتین)، منوی همبرگری و همهٔ مسیرها در موبایل (بدون اسکرول افقی)،
  جدول پیشنهاد خرید در ۱۲۰۰px، فرم‌های افزودن/ویرایش/بایگانی/بازیابی/حذف (پلتفرم، تراکنش، قیمت، دارایی)، حالت‌های بارگذاری/خطا/قطع شبکه/خالی **بازار جامع ایران در دسکتاپ و موبایل ۳۹۰px** (دیتابیس موقت با همان مسیر واقعی دریافت/پردازش پر می‌شود)، فرم اتصال نماد (جست‌وجو، پیش‌نمایش، تأیید صریح، تغییر و قطع اتصال) و **بازیابی از پشتیبان و پاک‌سازی کامل**.

## امنیت

اعتبارسنجی همهٔ ورودی‌ها با Pydantic، کوئری‌های پارامتری SQLAlchemy (بدون SQL خام)، لاگ خطاها در `data/logs`، سربرگ‌های امنیتی (و HSTS روی HTTPS در production)،
عدم وجود هیچ کلید API در جاوااسکریپت (کلیدها رمزنگاری‌شده و فقط‌نوشتنی‌اند)، مسدودسازی SSRF (آدرس‌های داخلی/localhost مگر با `PRICE_ALLOW_PRIVATE_HOSTS=true`)، فهرست میزبان مجاز (`ALLOWED_HOSTS`)، CORS بسته به‌طور پیش‌فرض (`CORS_ORIGINS`)، مستندات Swagger قابل خاموش‌کردن (`DOCS_ENABLED`) و Basic Auth اختیاری. پیام خطاهای ۵۰۰ عمومی است و جزئیات فقط در لاگ سرور می‌ماند. فایل دیتابیس و پشتیبان‌ها مجوز 600/700 می‌گیرند. جزئیات و فهرست بازبینی: `docs/SECURITY.md`.

همهٔ متغیرهای محیطی در `.env.example` توضیح داده شده‌اند.
