# CapitalPilot — کنترل سرمایه، تصمیم هوشمندانه

برنامهٔ وب فارسی و راست‌به‌چپ برای مدیریت سرمایه‌گذاری شخصی: داشبورد، چند سبد/استراتژی، دارایی‌ها و صندوق‌های کاملاً پویا، پلتفرم‌ها،
تراکنش‌ها، تقویم واریزی ماهانه، پیشنهاد خرید، مرکز ریسک، گزارش‌ها (Excel/CSV/PDF)، **موتور داده‌های بازار و صفحهٔ «منابع قیمت»**
و تنظیمات. نسخهٔ ۲ بدون بازنویسی ساخته شده و دادهٔ نسخهٔ ۱ با مهاجرت بدون‌اتلاف حفظ می‌شود.

> **این برنامه هیچ سفارش خرید یا فروشی ارسال نمی‌کند.** پیشنهادها فقط محاسبه‌اند؛ خرید را خودتان در پلتفرم انجام می‌دهید و سپس ثبت می‌کنید.
> این ابزار مشاورهٔ مالی نیست و هشدار افت سرمایه تضمینی برای جلوگیری از زیان بیشتر نیست.

## اجرای سریع

نیازمندی: Python 3.11 یا بالاتر (پیشنهادی ۳.۱۲+).

**Linux / Ubuntu / macOS**
```bash
./run.sh            # ساخت venv، نصب وابستگی‌ها و اجرا → http://127.0.0.1:8000
```

**Windows (PowerShell)**
```powershell
py -m venv .venv
.venv\Scripts\pip install -r requirements.txt
copy .env.example .env
.venv\Scripts\uvicorn app.main:app --port 8000
```

**Docker**
```bash
docker compose up --build        # دادهٔ برنامه در پوشهٔ ./data ذخیره می‌شود
```

مستندات Swagger: `http://127.0.0.1:8000/api/docs` — بررسی سلامت: `/api/health`

برای دسترسی از شبکه: `HOST=0.0.0.0 ./run.sh` (در این حالت حتماً `BASIC_AUTH_USER` و `BASIC_AUTH_PASSWORD` را در `.env` تنظیم کنید).

مبلغ بین پلتفرم‌ها طبق ترکیب هدف تقسیم و تراکنش‌های واقعی ساخته می‌شود.

## قوانین محاسباتی

* همهٔ محاسبات مالی در بک‌اند و با `Decimal` انجام می‌شود (فرانت‌اند فقط نمایش می‌دهد).
* تعداد واحد و قیمت خرید جدا ذخیره می‌شوند؛ کارمزد در بهای تمام‌شدهٔ خرید لحاظ می‌شود.
* بهای تمام‌شده با روش **میانگین موزون**؛ سود فروش = (تعداد × قیمت − کارمزد) − (میانگین × تعداد).
* سود/زیان تحقق‌یافته و تحقق‌نیافته جدا هستند. واریز سود نیست و برداشت در بازدهی لحاظ می‌شود
  (ارزش فعلی + برداشت‌ها − واریزی‌ها = کل سود/زیان).
* بازدهی زمانی (TWR) و **XIRR**؛ در صورت کمبود داده (مثلاً کمتر از ۳۰ روز یا نبود قیمت معتبر) به‌جای عدد، دلیل نمایش داده می‌شود.
* قیمت «امروز» فقط وقتی معتبر است که تأییدشده، ثبت‌شده تا همان لحظه، هم‌واحد با دارایی و جدیدتر از حد مجاز (پیش‌فرض ۳ روز) باشد.
  قیمت کهنه هرگز به‌عنوان قیمت روز نشان داده نمی‌شود و ارزش‌گذاری را «ناقص» می‌کند.
* ویرایش یا حذف تراکنش، کل دفتر را دوباره بازپخش می‌کند؛ اگر نتیجه ناسازگار باشد (مثلاً فروش بیش از موجودی) رد می‌شود.
* افت سرمایه (Drawdown) از شاخص زمانی بازده تعدیل‌شده با جریان نقدی محاسبه می‌شود تا واریز جدید افت را پنهان نکند.
* پیشنهاد خرید: فقط خرید، تعداد صحیح واحد، با قیمت روز و کارمزد؛ بدون پیشنهاد فروش برای رسیدن به وزن هدف.

## مدیریت دارایی‌ها، پلتفرم‌ها و سبدها (نسخهٔ ۲)

هیچ دارایی، صندوق یا پلتفرمی در کد ثابت نیست؛ همه از رابط کاربری اضافه، ویرایش و بایگانی می‌شوند.

* **دارایی‌ها و صندوق‌ها** یک ساختار مشترک دارند: نام فارسی/انگلیسی، نماد، نوع، بازار، پلتفرم، واحد سنجش، واحد پول، اعشار مجاز،
  حداقل مقدار خرید، وزن هدف، قیمت اولیهٔ خرید (اختیاری و فقط اطلاعاتی)، توضیحات، فعال/غیرفعال، منابع قیمت و شناسه در هر منبع
  (مثلاً insCode در TSETMC). هر نوع می‌تواند فیلدهای اختصاصی داشته باشد (مثلاً «نوع صندوق»، «عیار»).
* **انواع دارایی پویا:** صندوق، سهام، رمزارز، طلا، نقره، مس، ارز، درآمد ثابت، کالا، شاخص، سایر و هر نوع جدیدی که خودتان تعریف کنید
  (با رنگ و فیلدهای دلخواه) از «دارایی‌ها ← مدیریت انواع دارایی».
* **پلتفرم‌ها** بخش مستقل‌اند (مفید، بیت‌پین، بورس، بورس کالا، کارگزاری دیگر، بازار خارجی، شخصی، سایر + هر چه اضافه کنید).
  هر دارایی به یک پلتفرم وصل است؛ یک ابزار روی چند پلتفرم، به‌صورت دو دارایی با موجودی و شناسهٔ مستقل ثبت می‌شود.
* **سبدها/استراتژی‌ها:** هر سبد سرمایه، واریزی ماهانه، افق، سقف افت، تاریخ شروع، دارایی‌های عضو و وزن هدف خودش را دارد
  (حالت درصدی با مجموع دقیقاً ۱۰۰٪ یا مبلغ ثابت). تراکنش‌ها، برنامهٔ واریزی، ارزش‌گذاری و ریسک برای هر سبد جدا محاسبه می‌شود.
  سبد فعال را از کنار عنوان بالای صفحه عوض می‌کنید. حذف دارایی از یک سبد هرگز تراکنش‌هایش را پاک نمی‌کند.

### حذف امن (Soft delete)

| وضعیت | کار مجاز |
|---|---|
| دارایی/پلتفرم/سبد بدون تراکنش و وابستگی | حذف کامل (با تأیید) |
| دارای تراکنش | فقط **بایگانی**؛ سابقه، سود/زیان گذشته و گزارش‌ها حفظ می‌شود؛ در پیشنهاد خرید و ثبت خرید جدید ظاهر نمی‌شود؛ قابل بازیابی |
| دارای وابستگی ولی بدون تراکنش (قیمت، منبع، عضویت سبد) | حذف دائمی فقط پس از بررسی وابستگی‌ها و تأیید چندمرحله‌ای: درخواست ← تایپ عبارت «حذف دائمی» ← اجرا (توکن ۵ دقیقه‌ای، پشتیبان خودکار قبل از حذف) |

دارایی یا پلتفرمی که تراکنش دارد هیچ‌گاه حذف دائمی نمی‌شود.

## موتور داده‌های بازار و منابع قیمت

بسته‌ای مستقل در `app/services/marketdata/` با قرارداد یکسان برای همهٔ ارائه‌دهنده‌ها: قیمت جاری، اطلاعات نماد، تاریخچه،
بررسی سلامت، گزارش خطا، زمان آخرین دریافت و واحد قیمت.

| ارائه‌دهنده | توضیح | وضعیت راستی‌آزمایی |
|---|---|---|
| `TSETMCProvider` | آخرین معامله، قیمت پایانی، NAV (فقط وقتی معتبر باشد)، تاریخچه، زمان به‌روزرسانی، جستجو و انتخاب نماد؛ ریال به تومان تبدیل می‌شود | نشانی‌ها از کلاینت متن‌باز `pytse-client` ‏(0.19.1) |
| `BitpinProvider` | فهرست بازارها، قیمت لحظه‌ای و آخرین معامله، تغییر ۲۴ساعته، تاریخچه (TradingView bars) از API عمومی؛ فقط بازار تکی مثل `BTC_IRT`. **سبدهای آمادهٔ سرمایه‌گذاری تیکر نیستند** و رد می‌شوند (برای آن‌ها قیمت دستی یا منبع اختصاصی) | نشانی‌ها از پروژه‌های متن‌باز بیت‌پین؛ مستندات رسمی از سندباکس در دسترس نبود |
| `StreamDataProvider` | سهام/شاخص خارجی؛ آدرس و کلید از ENV یا پنل؛ قیمت و ارز ثبت می‌شود و تبدیل به تومان جدا با نرخ ارز ثبت‌شده انجام می‌شود | **بدون آدرس پیش‌فرض**؛ مستند عمومی راستی‌آزمایی نشد → آداپتور JSON قابل‌پیکربندی |
| `ServixProvider` | اختیاری (طلا، ارز و …) | همانند بالا |
| `CustomAPIProvider` | هر API با پاسخ JSON: آدرس، احراز هویت (None/Bearer/هدر/کوئری)، پارامترها، مسیر JSONPath یا نگاشت فیلد قیمت/زمان/واحد، ضریب | کاملاً کاربرمحور |
| `ManualPriceProvider` | ثبت دستی؛ همیشه به‌عنوان آخرین گزینه | — |

> **صادقانه:** محیط ساخت به سرویس‌های ایرانی دسترسی نداشت، پس اتصال زنده به TSETMC/بیت‌پین آزموده نشده است. آزمون‌های خودکار با `httpx.MockTransport`
> و نمونهٔ پاسخ‌های مستندشده انجام شده‌اند. پس از اجرا روی شبکهٔ خودتان از «منابع قیمت ← تست اتصال» استفاده کنید؛ هر ناهمخوانی در نشانی را
> می‌توانید با `TSETMC_BASE_URL` / `BITPIN_BASE_URL` یا در پنل اصلاح کنید. نرخ تبدیل ارز به تومان خودکار دریافت نمی‌شود و از جدول نرخ دستی می‌آید.

### صفحهٔ «منابع قیمت»
افزودن/ویرایش/غیرفعال/بایگانی منبع، آدرس، نوع احراز هویت، کلید API (فقط‌نوشتنی؛ **هرگز به مرورگر برنمی‌گردد**، با Fernet رمزنگاری می‌شود و در پشتیبان نیست)،
پارامترهای درخواست، مسیر JSON قیمت، واحد پول ورودی، بازهٔ به‌روزرسانی، تقویم بازار، سقف نرخ درخواست، تلاش مجدد، تست اتصال،
نتیجه و خطای آخرین درخواست، لاگ‌ها و تنظیمات زمان‌بند.

### اولویت منبع هر دارایی و قواعد اعتبار قیمت
* برای هر دارایی ترتیب منابع (اصلی ← جایگزین ← دستی) تعریف می‌شود. خطای منبع اصلی لاگ می‌شود و منبع بعدی امتحان می‌شود.
* اگر همه شکست بخورند، «در دسترس نیست یا کهنه» نشان داده می‌شود؛ **هیچ قیمت قدیمی‌ای به‌عنوان قیمت زنده نمایش داده نمی‌شود.**
* قیمت نامعتبر (صفر/منفی، ناهمخوانی واحد، آینده، کهنه) با دلیل در جدول ثبت می‌شود اما در ارزش‌گذاری و نمودار نمی‌آید و جایگزین قیمت معتبر نمی‌شود.
* قیمت تکراری (همان دارایی/منبع/زمان منبع/نوع) دوباره ذخیره نمی‌شود. قیمت خودکار فقط وقتی «تأییدشده» است که منبع «تأیید خودکار» داشته باشد؛ وگرنه تا تأیید دستی در ارزش‌گذاری نیست.
* هر رکورد قیمت: دارایی، منبع، قیمت، واحد، زمان دریافت، زمان منبع، اعتبار، تأیید و توضیح. صفحهٔ دارایی نمودار تاریخچه و مقایسهٔ منابع را نشان می‌دهد.

### زمان‌بند مستقل
بازهٔ پیش‌فرض و بازهٔ هر منبع/دارایی، فقط در ساعات بازار (بورس تهران: شنبه تا چهارشنبه ۰۸:۴۵–۱۲:۴۵ به وقت تهران؛ رمزارز ۲۴ساعته)،
کش ۱۵ ثانیه‌ای و حذف درخواست تکراری هم‌زمان، سقف نرخ درخواست، تلاش مجدد با backoff نمایی، لاگ و ثبت آخرین دریافت موفق.
با `SCHEDULER_ENABLED=false` کلاً خاموش می‌شود. تعطیلات رسمی شناسایی نمی‌شود (تقویم بازار فقط روزهای هفته و ساعت است).

### قیمت دستی و نرخ ارز
ورود دستی قیمت (با تاریخ/ساعت و تأیید) همیشه کار می‌کند؛ نرخ ارز جداگانه ثبت می‌شود.

## مرکز هوشمندی قیمت‌ها و کنترل کیفیت (نسخهٔ ۲٫۱)

صفحهٔ **«مرکز هوشمندی قیمت‌ها»** (`#/intelligence`) فقط می‌خواند، تحلیل می‌کند و پیشنهاد می‌دهد؛ **هیچ سفارش خرید یا فروشی ثبت نمی‌شود** و هر تصمیم مالی با تأیید دستی شماست.
همهٔ اعداد از قیمت‌ها و لاگ واقعی درخواست‌ها محاسبه می‌شود؛ هیچ داده نمایشی یا آزمایشی به‌عنوان قیمت واقعی نشان داده نمی‌شود.

* **نمای کلی منابع:** تعداد منابع فعال/غیرفعال/دارای خطا، آخرین دریافت موفق، زمان پاسخ، درصد موفقیت و تعداد خطا برای هر منبع.
* **پایش دارایی‌ها:** قیمت و واحد، منبع و منشأ (دستی/آنلاین)، زمان و سن قیمت، تأخیر داده، وضعیت (معتبر، قدیمی، نامعتبر، دستی، ناموجود، اختلاف منابع)، اختلاف قیمت بین منابع،
  زنجیرهٔ منابع (اصلی ← جایگزین)، تشخیص قطع منبع اصلی، «آخرین قیمت موفق» جدا از «آخرین تلاش دریافت»، و ردپای تبدیل (مقدار خام، واحد، ریال↔تومان، نرخ ارز).
  از همین‌جا اولویت منابع هر دارایی تغییر می‌کند و «مقایسه» قیمت را از همهٔ منابع می‌گیرد (برای دیدن اختلاف).
* **هشدارهای هوشمند** (در هر درخواست از وضعیت جاری محاسبه می‌شوند): قیمت قدیمی، اختلاف غیرعادی منابع، تغییر شدید، قطع منبع، واحد پول اشتباه، قیمت صفر/منفی/نامعتبر، عدم تطابق زمان داده با زمان دریافت.
* **گزارش عملکرد و تاریخچه:** نمودار نرخ موفقیت، زمان پاسخ، درخواست و خطای روزانهٔ هر منبع و جدول لاگ با فیلتر تاریخ (شمسی)، منبع، دارایی و نتیجه.

### لایهٔ کنترل کیفیت قیمت (`app/services/marketdata/quality.py`)
* قیمت آنلاین هیچ‌گاه بدون منبع و زمان دریافت ذخیره نمی‌شود؛ اگر منبع زمان قیمت را اعلام نکند برچسب `no_source_time` می‌خورد و زمان دریافت ثبت می‌شود.
* قیمت صفر/منفی، زمان آینده و قیمت کهنه ثبت می‌شود اما نامعتبر است، در ارزش‌گذاری نمی‌آید و **قابل تأیید نیست** (تأیید قیمت نامعتبر → خطای ۴۲۲).
* تبدیل ریال/تومان/ارز شفاف است: مقدار خام، واحد خام و توضیح تبدیل روی هر رکورد می‌ماند؛ تبدیل ارز خارجی خودکار و خاموش انجام نمی‌شود (نیاز به نرخ ارز ثبت‌شده).
* **اختلاف غیرعادی منابع** (پیش‌فرض بیش از ۱۰٪ بین قیمت‌های تازهٔ دو منبع): سیستم یکی را خودسرانه انتخاب نمی‌کند؛ دارایی در وضعیت «اختلاف منابع» می‌ماند و در ارزش‌گذاری نمی‌آید تا شما قیمت دستی تازه ثبت کنید یا یکی از قیمت‌ها را صریحاً تأیید کنید.
* هر قیمت دارای `origin` (`manual` / `online`) است؛ حذف یا تغییر منبع قیمت، منشأ و تاریخچهٔ قیمت‌های ثبت‌شده و تراکنش‌ها را تغییر نمی‌دهد.
* آستانه‌ها با `QUALITY_*` در `.env` قابل تنظیم است (`.env.example`).
* جایگزین فقط وقتی استفاده می‌شود که دادهٔ آن معتبر باشد، و مسیر کامل دریافت (`via`) روی رکورد ذخیره می‌شود.

API فقط‌خواندنی: `GET /api/market-data/intelligence/{overview,assets,alerts,performance,logs}`. گزینهٔ `POST /api/assets/{id}/refresh-price?all_sources=true` همهٔ منابع را برای مقایسه می‌خواند.

## مهاجرت پایگاه‌داده

هنگام اجرا، `app/migrations` نسخهٔ طرح‌واره را بررسی می‌کند. روی دیتابیس نسخهٔ ۱: ابتدا پشتیبان کامل فایل در `data/backups`، سپس مهاجرت در تراکنش
(`m001` پایه، `m002` مدیریت پویا، `m003` کیفیت قیمت: ستون‌های `origin`، قیمت خام، برچسب‌های کیفیت و …). همهٔ تراکنش‌ها، قیمت‌ها و تنظیمات حفظ می‌شود، یک «سبد اصلی» از تنظیمات قبلی ساخته می‌شود و تراکنش‌ها به آن وصل می‌شوند.
آزمون `tests/test_migration.py` همین مسیر را روی یک دامپ واقعی نسخهٔ ۱ اجرا و عددبه‌عدد (ارزش، سود/زیان، XIRR) مقایسه می‌کند.

## مستندات API

Swagger/OpenAPI تعاملی در `/api/docs` (و `/api/openapi.json`). گروه‌های اصلی:

| مسیر | کاربرد |
|---|---|
| `/api/assets` | فهرست (جستجو، فیلتر نوع/پلتفرم/وضعیت، مرتب‌سازی، صفحه‌بندی)، ساخت، ویرایش، `archive`، `restore`، `dependencies`، `price-sources`، `refresh-price`، `purge/request` و `purge/confirm` |

## گزارش‌ها

روزانه، ماهانه، فصلی، سالانه، کل دوره، سود و زیان هر دارایی، واریزی‌ها، برداشت‌ها، عملکرد پلتفرم‌ها، مقایسه با ترکیب هدف و ریسک.
خروجی Excel حاوی عدد واقعی (نه متن) با قالب هزارگان، CSV (UTF-8 با BOM) و PDF فارسی است.

## پشتیبان‌گیری و پاک‌سازی

* «تنظیمات ← دریافت پشتیبان JSON» و بازیابی از فایل (با تأیید و اعتبارسنجی کامل پیش از دست‌زدن به پایگاه‌داده).
* پشتیبان فایل دیتابیس روی سرور در `data/backups`.
* پاک‌سازی داده در چند مرحله: تأیید، تایپ عبارت امنیتی و اجرای نهایی؛ پیش از آن پشتیبان خودکار گرفته می‌شود.

## PostgreSQL

`pip install "psycopg[binary]"` و در `.env`: `DATABASE_URL=postgresql+psycopg://user:pass@localhost:5432/capitalpilot`.
مدل‌ها با SQLAlchemy 2 نوشته شده و ستون‌های پولی در SQLite به‌صورت متن (برای حفظ دقت Decimal) و در PostgreSQL به‌صورت `NUMERIC(38,12)` ذخیره می‌شوند.

## آزمون‌ها

```bash
pip install -r requirements-dev.txt
python -m pytest -q                      # همهٔ آزمون‌های Python (+ پوشش رابط کاربری در صورت وجود Node و Chrome)
```

* **Python:** محاسبات مالی، API، مدیریت پویا، موتور داده بازار، مهاجرت از دامپ واقعی نسخهٔ ۱ (شامل پُرشدن `origin`)، لایهٔ کنترل کیفیت (اعتبار قیمت، اختلاف منابع، fallback، هشدارها، آمار منابع و لاگ‌ها، آخرین قیمت موفق در برابر آخرین تلاش) و اینکه حذف/تغییر منابع، تراکنش‌ها و قیمت‌های ثبت‌شده را دست‌نخورده می‌گذارد.
* **رابط کاربری** (`tests/frontend`، با `tests/test_frontend.py` اجرا می‌شود و بدون Node یا مرورگر skip می‌شود):
  `cd tests/frontend && npm install` سپس `pytest tests/test_frontend.py`. یک سرور و دیتابیس موقت جدا بالا می‌آید (به داده‌های شما دست نمی‌زند).
  آزمون واحد `node:test` برای قالب‌بندی و تبدیل ورودی؛ آزمون Puppeteer برای: همهٔ مسیرها در دسکتاپ (بدون خطای کنسول و بدون رقم لاتین)، منوی همبرگری و همهٔ مسیرها در موبایل (بدون اسکرول افقی)،
  جدول پیشنهاد خرید در ۱۲۰۰px، فرم‌های افزودن/ویرایش/بایگانی/بازیابی/حذف (پلتفرم، تراکنش، قیمت، دارایی)، حالت‌های بارگذاری/خطا/قطع شبکه/خالی و **بازیابی از پشتیبان و پاک‌سازی کامل**.
  مرورگر: `CHROME_PATH`، Chrome/Chromium سیستم، یا بستهٔ `@sparticuz/chromium`.

## امنیت

اعتبارسنجی همهٔ ورودی‌ها با Pydantic، کوئری‌های پارامتری SQLAlchemy (بدون SQL خام)، لاگ خطاها در `data/logs`، سربرگ‌های امنیتی،
عدم وجود هیچ کلید API در جاوااسکریپت (کلیدها رمزنگاری‌شده و فقط‌نوشتنی‌اند)، مسدودسازی SSRF (آدرس‌های داخلی/localhost مگر با `PRICE_ALLOW_PRIVATE_HOSTS=true`)، فهرست میزبان مجاز اختیاری و Basic Auth اختیاری.

همهٔ متغیرهای محیطی در `.env.example` توضیح داده شده‌اند.
